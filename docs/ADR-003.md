# ADR-003 — Arrow vs JSON IPC, deviasi struktur six-layer, dan penegakan Pyright

**Status:** Accepted (2026-11-07) · **Closes:** K3 (Audit 2026-11-07 §3.2), utang struktural §5.2.6
(Audit 2026-11-07) · **Related:** AGENTS.md baris Arrow diperbarui dengan footnote ADR-003;
keputusan Pyright final di P1-4.

## Decision

1. **IPC tetap JSON untuk MVP dengan cap payload** — preview ≤ 200 baris, scatter
   ≤ 2000 titik, bin histogram ≤ 30. Klaim "Arrow IPC (M2+)" di AGENTS.md dinyatakan
   **belum diterapkan**; Arrow (PyArrow) dipakai hanya sebagai format penyimpanan/
   baca-tulis Parquet dan CSV di dalam backend (`ingestion.py`, `histograms.py`,
   `bivariate.py`, `cleaning.py`), bukan sebagai format IPC antar-proses.
2. **Deviasi sadar dari struktur six-layer (ES-5.1)** ke flat modules di `backend/`
   (`application.py` sebagai orkestrator, `ipc.py` sebagai boundary, `persistence.py`
   sebagai repository port, `contracts.py` sebagai kontrak, modul fitur per domain),
   karena arah dependensi bersih dan tidak ada dependensi melingkar antar-modul.
3. **Pyright:** penegakan diputuskan di kartu P1-4 (pasang strict atau tunda dengan
   ADR amandemen). ADR-003 ini tidak memasang Pyright; status quo (ruff + pytest
   sebagai gate §10) tetap berlaku sampai P1-4 diputuskan.
   **Amandemen P1-4 (2026-11-07):** Pyright strict **ditunda ke M4**. Bukti
   penilaian: pyright 1.1.414 `typeCheckingMode: strict` pada `backend/` (17 file,
   4.246 baris) menghasilkan **1.288 error** — dominan `reportUnknown*` karena
   pyarrow (mesin data inti), openpyxl, dan reportlab **tidak menyertakan
   `py.typed`** sehingga member mereka berstatus Unknown di semua jalur data;
   strict penuh tidak tercapai hanya dengan anotasi tanpa menyebar `Any`/cast di
   boundary pyarrow (melebihi estimasi 2–4 jam kartu, tanpa perbaikan keamanan
   tipe yang sepadan). Mode basic menghasilkan 80 error (74 di antaranya akses
   atribut dinamis pada `BaseModel` di dispatch `ipc.py`, sisanya 6 temuan argumen/
   opsional yang dicatat sebagai follow-up M4). Status quo gate §10 (ruff + pytest)
   tetap berlaku; tidak ada `pyrightconfig.json` / step CI yang dipasang.

## Context

- Doc06 §9 (IPC-008, Confirmed) dan Doc04 §10.3 mensyaratkan payload policy: jangan
  pernah serialisasi whole DataFrame lewat JSON IPC; payload kecil → JSON DTO,
  preview → baris/kolom terbatas, pertukaran medium/besar → Arrow IPC, hasil besar
  → referensi artefak. AGENTS.md menerjemahkan ini sebagai "analytics payloads use
  Arrow IPC (M2+)".
- Realitas implementasi (audit K3): seluruh IPC lewat PyWebView bridge
  (`backend/ipc.py`) berformat JSON (`Response` Pydantic), tanpa satu pun jalur
  Arrow IPC. Prinsip IPC-008 dipatuhi lewat cap numerik, bukan lewat Arrow:
  preview `limit` divalidasi `le=200` (`contracts.py:118`), scatter dipotong
  `pairs[:_SAMPLE_MAX]` dengan `_SAMPLE_MAX = 2000` (`bivariate.py:24,155`) dan
  dikunci `_BIVAR_SAMPLE_MAX = 2000` (`contracts.py:288`), bin histogram dibatasi
  `_MAX_BINS = 30` (`histograms.py:22,53`). Payload agregat yang dihasilkan
  (profil, histogram, quality, bivariate ringkasan) kecil dan terukur.
- Struktur: Doc02 §4 + ES-5.1 mendokumentasikan arsitektur six-layer. Implementasi
  nyata adalah flat modules tanpa paket layer; `application.py` mengoordinasikan
  semua modul fitur, `ipc.py` hanya menerjemahkan ke kontrak, `persistence.py`
  satu-satunya modul menyentuh SQL (port ADR-002 dipertahankan), dan tidak ada
  sirkularitas import antar-modul fitur yang teramati (verifikasi 2026-11-07 via
  grep import `backend/*.py`).
- Pyright strict (Freeze package E) tidak dipasang: tidak ada `pyrightconfig.json`,
  tidak ada `[tool.pyright]` di `pyproject.toml`, tidak ada step di CI
  `.github/workflows/ci.yml` (verifikasi 2026-11-07, grep nol).

## Alternatives considered

- **Arrow IPC sekarang (ditolak untuk MVP):** menutup K3 sepenuhnya, tetapi
  menambah kompleksitas bridge (serialisasi biner PyWebView, kontrak TS, pengujian
  round-trip) untuk payload yang hari ini terukur kecil (≤ 200/2000/30). Biaya
  melebihi nilai sampai ada payload yang membuktikan kebutuhan.
- **Struktur six-layer penuh sekarang (ditolak):** memecah `backend/` ke paket
  layer (`domain/`, `application/`, `infrastructure/`, dst.) tanpa perubahan
  perilaku. Refactoring mekanis berisiko regresi dan menyulitkan review; nilai
  utamanya (penegakan boundary oleh CI, ES-7.2) belum diperlukan selama arah
  dependensi tetap bersih dan direview.
- **Pyright strict sekarang (ditunda ke P1-4):** memberi pengetikan lebih ketat
  di seluruh `backend/`, tetapi audit memperkirakan 2–4 jam perbaikan anotasi;
  diputuskan terpisah agar ADR-003 ini dapat ditutup dalam estimasi 1 jam tanpa
  mengikatnya pada kerja anotasi.

## Consequences

- AGENTS.md baris "No whole-DataFrame JSON over IPC; analytics payloads use Arrow
  IPC (M2+)" diperbarui dengan footnote: status Arrow IPC = belum diterapkan per
  ADR-003; JSON + cap (preview ≤ 200, scatter ≤ 2000, bin ≤ 30) adalah kebijakan
  aktif sampai trigger revisit terpenuhi. Larangan whole-DataFrame JSON tetap
  berlaku penuh.
- Cap payload adalah bagian kontrak: menaikkan cap di atas nilai ADR ini
  memerlukan amandemen ADR-003.
- Revisit trigger Arrow: payload agregat apa pun melebihi 100 KB dalam satu
  respons IPC, atau kebutuhan scatter > 2000 titik, atau fitur baru yang
  mengembalikan data tabular mentah (bukan agregat) — saat itu Arrow IPC
  dievaluasi sebagai pengganti JSON untuk jalur tersebut.
- Revisit trigger struktur: migrasi Arrow dan/atau plugin menuntut boundary
  modul yang lebih keras (mis. import-graph CI per ES-7.2) — saat itu struktur
  six-layer dirombak secara eksplisit, bukan bertahap diam-diam.
- Revisit trigger Pyright: terpenuhi bila (a) pyarrow/openpyxl/reportlab
  menyertakan `py.typed` atau stub tersedia, atau (b) strict diterapkan bertahap
  mulai dari modul bertipe penuh (`contracts.py` pydantic-only) lalu boundary
  `ipc.py` — saat itu pasang `pyrightconfig.json`, step CI, dan perbaiki anotasi
  sebagai kartu M4. Baseline penilaian P1-4: strict 1.288 error / basic 80 error
  (pyright 1.1.414, 2026-11-07); tracking: `docs/status-register.md` kartu P1-4.
- Reversible: ketiga keputusan ini terdokumentasi tanpa perubahan perilaku
  runtime; membalik keputusan hanya memerlukan ADR amandemen + refactor terencana.
