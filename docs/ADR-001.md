# ADR-001 — Pydantic→TypeScript contract generator

**Status:** Accepted (2026-11-05) · **Closes:** OD-9 (generator part), Baseline Freeze v1.0 package E

## Decision
Keep the custom generator in `tools/generate_types.py` (Pydantic JSON Schema → TS interfaces)
as the contract generator for M1–M2. `datamodel-codegen` is the documented fallback.

## Context
SYS-016 + IPC-001..005 require TS types generated from Pydantic, never hand-edited.
A generator must exist before frontend/backend work parallelises (contract-first, Step 1).

## Alternatives considered
- **Custom generator (chosen):** zero new dependency, already working and verified by
  `tsc --noEmit` + vite build; sufficient for current schema complexity (flat models,
  enums, optionals). Weak on deeply nested generics/unions.
- **datamodel-codegen:** stronger schema handling, but adds an external tool dependency
  whose abandonment would stall the contract pipeline; migration cost now exceeds value.

## Consequences
- Output file `frontend/src/shared/ipc/generated.ts` is marked GENERATED; CI runs
  `python tools/generate_types.py` + `tsc --noEmit` as the contract gate.
- Revisit trigger: schema complexity that breaks the custom generator (nested generics,
  discriminated unions) or a second consumer language — then switch and diff outputs.
- Reversible: both generators produce the same file path and interface names.
