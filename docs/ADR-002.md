# ADR-002 — Persistence: stdlib sqlite3 + repository port

**Status:** Accepted (2026-11-05) · **Closes:** OD-9 (ORM part), OD-11 detail (storage),
Baseline Freeze v1.0 packages E, J

## Decision
Use Python stdlib `sqlite3` behind the `Store` repository port in `backend/persistence.py`
(WAL + FK enforced). No ORM in M1–M2.

## Context
Doc04 requires a repository contract + unit-of-work shape; OD-11 delegates SQLite
implementation detail. M1 operations are flat CRUD (projects, datasets, jobs, events).

## Alternatives considered
- **stdlib sqlite3 + repository (chosen):** zero dependency, already implemented and
  tested; the port isolates storage so an ORM can be introduced later without touching
  domain/application/IPC layers.
- **SQLAlchemy Core:** value appears with dynamic joins/filter builders (M2+ analytics
  queries). Adopting it now adds abstraction for problems not yet present (YAGNI).

## Consequences
- `Store` is the only module touching SQL; domain objects never leak persistence types.
- Revisit trigger: first dynamic query builder need (M2 profiling filters) — evaluate
  SQLAlchemy Core at that point; migration is confined to `persistence.py`.
- OD-11 remaining detail (UUID v7 done in `domain.new_id`; flat Parquet snapshots done
  in M1-next) — no further open items from this package.
